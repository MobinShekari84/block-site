# Javascript Data Structure

This document establishes the uniform schema pattern for all data definitions residing in `/js/data`. By centralizing and standardizing this data, we strictly separate content from UI logic.

## Directory Tree

```text
/js/
├── data/
│   ├── index.js             # Central hub exporting all manually curated data
│   ├── projects.js          # Array of all project metadata and configurations
│   ├── siteMeta.js          # Global UI strings and translations
│   ├── aboutData.js         # Content for the About Us page
│   └── assetManifest.js     # AUTO-GENERATED mapping of project directories
```

## Schemas

### 1. `projects.js` Schema

Exports a `projects` array containing uniform project objects. Note that image galleries are **not** defined here; they are automatically populated from `assetManifest.js` by matching the `id` field.

```typescript
type BilingualString = {
  en: string;
  fa: string;
};

type ProjectItem = {
  id: string;               // Unique string identifier (MUST match asset folder name!)
  slug: string;             // URL-friendly string used for routing
  title: BilingualString;
  category: BilingualString;
  year: number;
  location: BilingualString;
  description: BilingualString;
  coverImage: string;       // Used for hero banner and thumbnails
  specs: {
    area?: BilingualString;
    status?: BilingualString;
    materials?: BilingualString;
    architect?: BilingualString;
  };
  isFeatured: boolean;       // Determines display on homepage slider
  heroTheme: 'light' | 'dark'; 
  
  // Optional Spatial Plan Config
  spatialPlan?: {
    planImageUrl: string;    // Path to the 2D architectural plan
    aspectRatio: string;     // e.g. "1755 / 2482"
    hotspots: Array<{
      id: number;
      x: number;             // X percentage on the plan
      y: number;             // Y percentage on the plan
      rot: number;           // FOV Cone rotation in degrees
      title: BilingualString;
      zone: BilingualString;
      renderUrl: string;     // Path to the 3D render at this hotspot
    }>;
  };
};
```

### 2. `assetManifest.js` Schema (Auto-Generated)

Do **not** edit this file manually. It is generated by running `node generator-apps/generate_assets.mjs`.

```typescript
type AssetManifest = Record<string, {
  exteriorDesign: string[];
  interiorDesign: string[];
  landscapeDesign: string[];
  documents: string[];
  photos: string[];
}>;

// Example
export const assetManifest = {
  "damas-villa": {
    "exteriorDesign": ["/assets/villa/Damas-Villa/exterior-design/facade.webp"],
    "interiorDesign": [],
    "landscapeDesign": [],
    "documents": ["/assets/villa/Damas-Villa/documents/ground-floor.webp"],
    "photos": []
  }
}
```

### 3. `aboutData.js` Schema

Centralizes all text and team member configurations for the About Us page.

```typescript
export const aboutData = {
  hero: {
    title: BilingualString,
    subtitle: BilingualString
  },
  narrative: BilingualString,
  team: Array<{
    id: string;
    name: BilingualString;
    role: BilingualString;
    bio: BilingualString;
    portraitPath: string;
    credentials: BilingualString;
    order: number;
    social: { linkedin: string; instagram: string; }
  }>,
  gallery: Array<{
    id: string;
    imagePath: string;
    caption: BilingualString;
  }>,
  philosophy: Array<{
    index: string;
    title: BilingualString;
    text: BilingualString;
  }>,
  contact: {
    email: string;
    phone: string[];
    address: BilingualString;
    hours: BilingualString;
  }
};
```
